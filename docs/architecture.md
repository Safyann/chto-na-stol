# Архитектура «Что на стол?»

Приложение работает с личной коллекцией на одном устройстве. Это позволяет сохранить подборку, шпаргалки и отметки о партиях доступными за игровым столом при слабом интернете.

## Слои Feature-Sliced Design

| Слой                                                | Ответственность                                                                                               |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| [app](../src/app)                                   | Точка входа, навигация по hash, общая коллекция в памяти, открытие диалога из обоих разделов и обновление PWA |
| [pages/selection](../src/pages/selection)           | Условия игрового вечера, фильтрация, порядок рекомендаций и пояснения                                         |
| [pages/collection](../src/pages/collection)         | Список игр и действия с коллекцией, включая выбор файла для переноса                                          |
| [features/manage-game](../src/features/manage-game) | Диалог просмотра шпаргалки и форма добавления или редактирования игры                                         |
| [entities/game](../src/entities/game)               | Тип игры, чтение и запись коллекции, валидация импорта и карточка                                             |
| [shared](../src/shared)                             | Общие стили элементов интерфейса и работа с локальными датами                                                 |

Страницы независимы. Они получают игры от приложения и сообщают о действиях через пропсы. Правила подбора принадлежат странице подбора, поскольку именно там задаются условия вечера и порядок результатов. Карточка принадлежит сущности игры, поскольку используется в обеих страницах. Компоненты и их CSS Modules лежат рядом.

Импорты между срезами идут на нижние слои через публичный `index.ts`. Внутри среза файлы используют прямые относительные импорты. В `shared` импортируют нужный сегмент. [Слои FSD](https://feature-sliced.design/docs/reference/layers) · [Публичные API](https://feature-sliced.design/docs/reference/public-api)

## Данные и подбор

`Game` хранит диапазон игроков, длительность в минутах, отметку для новичков, дату последней партии и поля шпаргалки. Дата записывается в формате `YYYY-MM-DD` по календарю устройства. Пустая строка обозначает неизвестную дату.

Список доступных дополнений хранится отдельно от состава последней партии. Состав записывается при нажатии «Сыграли» и хранит названия на момент партии. Пустой список обозначает партию в базовую игру. В старых записях состав отсутствует.

Подбор отбрасывает игры, которые выходят за выбранные ограничения по числу игроков и времени или не подходят новичкам, когда те есть в компании. Из оставшихся показываются до трёх игр. Обычный режим поднимает игры со шпаргалкой, затем более длинные партии в пределах бюджета времени. Режим «Давно не играли» сначала сравнивает известные даты от самой давней к свежей. При одинаковых датах применяет обычный порядок.

Коллекция хранится в `localStorage` под ключом `chto-na-stol.collection.v1`. Она привязана к адресу приложения и профилю браузера. При чтении старых данных приложение пропускает записи с `demo: true`. При переносе из версии, которую открывали как файл, приложение проверяет JSON и объединяет записи по идентификатору. При совпадении идентификатора личная запись из текущей коллекции имеет приоритет.

## Офлайн-сборка

Навигация по `#selection` и `#collection` позволяет открывать разделы на статическом хостинге. Относительные пути сборки Vite поддерживают публикацию в подкаталоге.

После сборки [prepare-offline.mjs](../scripts/prepare-offline.mjs) формирует `dist/sw.js` из [шаблона](../scripts/worker.js) и списка ресурсов. Хеш содержимого определяет версию кэша. Сервис-воркер сохраняет ресурсы после первого открытия онлайн. Новая версия ждёт подтверждения в интерфейсе, затем активируется и перезагружает приложение. Данные коллекции хранятся отдельно от кэша ресурсов.

## Проверки

Vitest проверяет порядок подбора и перенос коллекции с датами, шпаргалками и личными правками. Для проверки интерфейса пройдите [сценарий из README](../README.md#попробовать), затем перезагрузите страницу и убедитесь, что дата партии сохранилась. Для проверки PWA повторите сценарий в production-сборке при отключённой сети.
